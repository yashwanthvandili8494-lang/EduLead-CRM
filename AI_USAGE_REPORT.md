### AI OUTPUT THAT WAS WRONG:
1. **React Hooks Rule Violation (`NewLeadModal.jsx`):** The AI placed an early return `if (!isOpen) return null;` on line 25, **above** a `useEffect` hook that handles debounced duplicate phone/email checking.
2. **Initial Duplicate Handling:** An early version simply threw an HTTP 400 error on duplicate phone/email rather than returning structured duplicate match metadata to allow secondary linkage.

---

### HOW I IDENTIFIED THE PROBLEM:
1. When opening the "+ New Lead" modal in production on Vercel, the app crashed and the Error Boundary captured `Minified React error #310` (*"Rendered more hooks than during the previous render"*).
2. Investigated the component lifecycle: when `isOpen` was `false`, 4 hooks were executed, but when `isOpen` changed to `true`, the `useEffect` hook was reached, causing a hook count mismatch between renders.

---

### HOW I FIXED IT:
1. Reordered the component logic in `client/src/components/NewLeadModal.jsx`: moved `if (!isOpen) return null;` to **after** all hook declarations, and placed an internal guard `if (!isOpen) return;` inside the `useEffect` callback. This ensured the exact same number of hooks executes unconditionally on every render cycle.
2. Implemented a dedicated duplicate check endpoint (`POST /api/leads/check-duplicate`) and added duplicate warning UI cards that display matching leads with student name, source, and an option to "Create Anyway as Linked Secondary Lead".
